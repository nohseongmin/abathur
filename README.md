# 개조식 (gaejosik)

**한국어로 AI 코딩 에이전트를 쓰면 토큰이 더 나간다. 그걸 줄이는 Claude Code 스킬 — 그리고 그 주장을 실제로 재는 도구.**

한국어는 같은 의미를 영어보다 **1.70배** 많은 토큰으로 표현한다(이 레포 실측, `o200k_base`). 출력 토큰은 입력보다 단가가 비싸므로, 한국어 사용자는 같은 작업에 구조적으로 더 많은 비용과 더 빠른 한도 소진을 감수한다.

개조식은 한국 공문서·보고서의 문체다. 인사·헤지·재진술을 걷어내고 `항목: 내용`으로 쓴다. 이 스킬은 Claude가 한국어로 답할 때 그 문체를 쓰게 만든다.

**답변 한 통 기준 실측 절감: 68%** (아래 표본 5종, `o200k_base`).

## 왜 감으로 만들면 안 되나

한국어 압축에는 글자 수와 토큰 수가 어긋나는 지점이 있다.

| 흔한 직관 | 글자 수 | 실제 토큰 |
|---|---|---|
| `토큰 만료 검사 오류` → `토큰만료검사오류` | 줄어듦 | **33% 증가** |
| `確認`(한자), `ㅇㅋ`(자모), `셋파`(즉석 축약) | 줄어듦 | **0% 절감** |
| `추가되었습니다` → `추가됨` | 줄어듦 | 0~43%, **중앙값 17%** (기대보다 작음) |
| `그래서` → `→` | 줄어듦 | 이득 있음 (접속사 한정) |
| `.` → `→` | 같음 | **0% 절감** |

마지막 두 줄이 이 프로젝트의 요지다. **같은 화살표 규칙이 무엇을 대체하느냐에 따라 이득이 되기도 하고 0이 되기도 한다.** 영어에서는 아예 성립하지 않는다(`causes`도 1토큰이라 원본 caveman은 화살표를 금지한다). 언어가 바뀌면 규칙의 부호가 바뀐다.

절감의 대부분은 잔재주가 아니라 **문장을 통째로 지우는 것**(인사·헤지·재진술·마무리멘트, 60~100%)에서 나온다. 어미와 기호는 마지막에 손대는 것이다.

그래서 이 레포는 규칙을 주장하지 않고 **측정**한다. 규칙을 이득 큼 / 이득 작음 / 이득 없음 3단으로 나누고, 분류가 틀리면 CI가 깨진다.

## 설치

### Claude Code 스킬로 쓰기

```bash
claude
```

```
/plugin marketplace add nohseongmin/gaejosik
/plugin install gaejosik
```

이후 "개조식", "간결하게", "토큰 아껴"라고 하거나 `/gaejosik`을 부르면 적용된다. 강도는 `/gaejosik lite|full|ultra`, 해제는 "개조식 끄기".

### 측정 도구로 쓰기

```bash
pip install -e .
```

```bash
python -m gaejosik bench
```

```bash
python -m gaejosik count README.md --price-per-mtok 15
```

`bench`는 규칙 코퍼스 전체를 실측한다. `--format markdown|json`, `--encoding cl100k_base`로 대조 가능.

실제 Claude 토크나이저 수치가 필요하면(`ANTHROPIC_API_KEY` 필요):

```bash
python -m gaejosik bench --anthropic
```

> ⚠️ `--anthropic`을 켤 때만 텍스트가 외부로 나간다. 기본 동작(`bench`, `count`)은 사용자 텍스트를 전송하지 않는다. 단 tiktoken이 최초 1회 BPE 인코딩 파일을 내려받는다(이후 로컬 캐시).

## 한계 — 정직하게

- **Claude의 토크나이저는 공개되지 않았다.** 기본 측정은 tiktoken `o200k_base`(GPT-4o/5 계열)를 프록시로 쓴다. `cl100k_base`에서도 결론이 같은지 CI가 확인하지만, Claude에서의 정확한 수치는 `--anthropic`으로 직접 재야 한다.
- **68%는 통제된 표본의 수치다.** 실제 세션은 코드 블록·파일 경로·에러 문자열 비중이 크고 그 부분은 압축하지 않는다. 실사용 절감률은 이보다 낮게 나오는 것이 정상이다.
- **모든 상황에 켜는 게 아니다.** 보안 경고, 되돌릴 수 없는 작업 확인, 순서가 중요한 절차에서는 스킬이 스스로 압축을 푼다.

## 규칙 추가하기

1. `src/gaejosik/rules.py`에 문장 쌍(`verbose`/`terse`)을 넣는다.
2. `python -m gaejosik bench`로 잰다.
3. 15% 이상 줄면 `RULES`, 아니면 `ANTI_RULES`에 남긴다 — 효과 없는 규칙도 "해봤고 안 됐다"는 기록으로서 가치가 있다.
4. `pytest`가 통과하면 `SKILL.md`에 옮긴다.

## 관련 프로젝트

먼저 나온 것들이 있다. 정직하게 적는다.

| 프로젝트 | 접근 | 이 레포와의 관계 |
|---|---|---|
| [caveman](https://github.com/JuliusBrussee/caveman) | 영어 caveman 문체로 출력 압축. "사용자 언어 유지" 규칙이 있어 한국어 질문에는 한국어로 압축해 답한다 | **원류.** 측정 문화("`cfg`는 `configuration`과 같은 수로 쪼개진다")를 여기서 가져왔다. 한국어 특화 규칙과 측정은 없다 |
| [cavemankorean](https://github.com/blacknabis/cavemankorean) | 위 포크 + 한국어 규칙 블록 | **가장 가까운 선행 작업.** 조사 생략·완곡 표현 삭제·접속사→화살표 등은 재보니 맞았다. 다만 한국어 벤치마크는 없고(65~75% 수치는 영어 태스크 측정치), 2026-04-12 포크 이후 갱신이 없어 원류가 그 뒤 바꾼 규칙들이 반영돼 있지 않다 |
| [k-laude](https://github.com/realkim93/k-laude) | 한글 입력을 온디바이스 LLM으로 영역해 전달 | **다른 레이어**(입력 토큰). macOS 26 + Apple Silicon 전용. 출력까지 줄이려면 답변을 영어로 받아야 한다 — 한국어로 읽겠다는 요구 자체를 없애는 방향이라 이 레포와 목표가 다르다 |
| [tokensave](https://github.com/epoko77-ai/tokensave) | 멀티에이전트 하네스의 모델 티어·캐싱 비용 감사 | 다른 레이어(하네스 아키텍처). 문체와 무관 |

이 레포가 더하는 것은 아이디어가 아니라 **측정**이다: 한국어 규칙을 3단으로 분류하고, 분류가 틀리면 테스트가 깨지게 만든 것.
